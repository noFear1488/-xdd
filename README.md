# yandex-nosite

Автоматический поиск бизнесов **без сайта** по данным Яндекс Карт — с выгрузкой
готового списка для обзвона в Excel, CSV или JSON.

Инструмент работает через **официальный [Search API Яндекс Карт][api]** (поиск по
организациям). Никакого парсинга вёрстки карт: это нарушает условия использования
сервиса, ломается при каждом релизе Яндекса и приводит к блокировке по IP.

[api]: https://yandex.ru/maps-api/docs/search-api/

---

## Что он делает

1. Берёт область (город из справочника, произвольный прямоугольник или круг вокруг точки).
2. Обходит её адаптивной сеткой, запрашивая организации по списку рубрик.
3. Для каждой организации определяет, **есть ли у неё настоящий сайт**.
4. Считает «оценку лида» — насколько бизнес перспективен для продажи сайта.
5. Складывает всё в локальную базу и выгружает файл, с которым можно идти звонить.

### Ключевая идея: «нет сайта» — это не только пустое поле

Организация, у которой в карточке пусто, — очевидный лид. Но их мало, а рядом
лежат случаи не хуже, которые обычный фильтр «url пустой» пропускает:

| Статус | Что означает | Пример |
|---|---|---|
| `сайта нет` | поле пустое | — |
| `только соцсети` | вместо сайта ссылка на соцсеть или мессенджер | `vk.com/salon`, `t.me/barber` |
| `только агрегатор` | вместо сайта чужая карточка | `zoon.ru/...`, `prodoctorov.ru/...` |
| `конструктор/поддомен` | визитка на бесплатном хостинге | `salon.tilda.ws`, `x.business.site` |
| `свой сайт` | собственный домен — **не лид** | `salon-krasoty.ru` |

По умолчанию в выгрузку попадают первые четыре категории. Флаг `--strict`
оставляет только те, у которых нет вообще никаких ссылок.

Дополнительно `--verify-sites` проверяет, открывается ли указанный сайт. Бизнес,
у которого сайт есть в карточке, но домен уже не отвечает, — один из самых
горячих лидов, и такие поднимаются в топ списка.

## Установка

Зависимостей нет — только Python 3.10+.

```bash
git clone <repo>
cd yandex-nosite
python3 -m pip install -e .     # появится команда yandex-nosite
```

Можно и без установки: `python3 -m yandex_nosite <команда>`.

## Ключ API

1. Зайдите в [кабинет разработчика Яндекса](https://developer.tech.yandex.ru/services/).
2. Подключите сервис **«JavaScript API и HTTP Геокодер»** → в нём получите ключ
   для **Поиска по организациям** (Search API).
3. Положите ключ в `.env` рядом с проектом:

```
YANDEX_MAPS_API_KEY=ваш-ключ
```

Бесплатный тариф — **500 запросов в сутки**. Это главное ограничение, и вся
логика инструмента построена вокруг его экономии (см. ниже).

## Быстрый старт

Посмотреть, как всё работает, можно **без ключа** — на синтетических данных:

```bash
python3 -m yandex_nosite scan --demo --region moscow --preset quick --out demo.xlsx
```

Реальный сценарий — три шага:

```bash
# 1. Сколько это будет стоить в запросах (1 запрос на рубрику на разведку)
yandex-nosite plan --region kazan --preset beauty

# 2. Собрать лидов
yandex-nosite scan --region kazan --preset beauty --out kazan-beauty.xlsx

# 3. Выгрузить из базы только самое горячее
yandex-nosite export --min-score 70 --out hot.csv
```

## Команды

| Команда | Назначение |
|---|---|
| `scan` | обойти область и собрать лидов |
| `plan` | оценить, сколько запросов и организаций даст сканирование |
| `export` | выгрузить накопленную базу с фильтрами |
| `stats` | статистика базы и расход суточной квоты |
| `regions` | список городов справочника |
| `presets` | список наборов рубрик |
| `check` | проверить, как классифицируется конкретный адрес сайта |

### Как задать область

```bash
--region kazan                       # город из справочника (yandex-nosite regions)
--bbox '49.05,55.75~49.25,55.85'     # прямоугольник lon,lat~lon,lat
--center '49.12,55.79' --radius 2    # круг радиусом 2 км вокруг точки
```

### Как задать рубрики

Search API ищет по тексту, поэтому «выгрузить весь город одним запросом» нельзя —
нужен список рубрик. Есть готовые наборы (`yandex-nosite presets`):
`quick`, `beauty`, `medicine`, `auto`, `food`, `services`, `education`, `sport`,
`retail`, `b2b`, `all`.

```bash
--preset beauty,medicine             # несколько наборов сразу
--query 'барбершоп' --query 'ногтевая студия'
--queries-file my-niches.txt         # свой список, по строке на рубрику
```

### Полезные флаги `scan`

```bash
--strict              # только организации совсем без ссылок
--statuses none,social  # явный выбор статусов
--min-score 60        # отбросить слабые лиды
--limit 300           # остановиться, набрав 300 организаций
--verify-sites        # проверить, открываются ли указанные сайты
--max-requests 200    # жёсткий потолок запросов за прогон
--out leads.xlsx      # формат определяется по расширению: .xlsx, .csv, .json
```

## Как расходуется квота

API отдаёт максимум **50 объектов на запрос**, сколько бы ни нашлось. Наивный
обход равномерной сеткой тратит квоту на пустые окраины и всё равно теряет
данные в плотном центре.

Здесь область делится **адаптивно**: тайл дробится на четыре, только если
в нём объектов больше, чем помещается в один ответ. Спальный район остаётся
одним запросом, центр дробится до нужной глубины. Плюс к этому:

- **Кэш ответов в SQLite.** Повторный запуск той же области квоту не тратит
  (`--cache-ttl`, по умолчанию 14 дней; отключается `--no-cache`).
- **Бюджет прогона.** `--max-requests` останавливает работу заранее; собранное
  при этом не теряется — оно сохраняется в базу и выгружается.
- **Учёт расхода по дням.** `yandex-nosite stats` показывает, сколько запросов
  ушло сегодня, чтобы не упереться в лимит посреди работы.
- **Команда `plan`.** Тратит по одному запросу на рубрику и говорит, во сколько
  обойдётся полный обход и хватит ли суточной квоты.

Практический ориентир: один средний город по одному пресету (8–15 рубрик) —
это примерно 100–300 запросов, то есть укладывается в суточный бесплатный лимит.
Большой город целиком по `--preset all` придётся разбить на несколько дней.

## Оценка лида

Каждой организации присваивается оценка 0–100 и список причин — он попадает
в выгрузку колонкой «Почему лид», чтобы менеджер понимал, зачем звонит.

Что повышает оценку: полное отсутствие сайта; неработающий сайт; наличие
телефона; отзывы и рейтинг (бизнес живой, а не брошенная карточка); указанный
режим работы; ниша с высоким спросом на сайт (медицина, юристы, ремонт, авто).
Что понижает: отсутствие телефона, пометка «закрыто», отсутствие адреса.

Веса собраны в `yandex_nosite/scoring.py` — правьте под свой рынок, там
обычный словарь.

## Результат

Выгрузка (`.xlsx` / `.csv` / `.json`) содержит: название, рубрику, телефоны,
адрес, статус сайта, найденные ссылки, оценку лида и причины, рейтинг, число
отзывов, режим работы, координаты, ссылку на карточку в Яндекс Картах и ID
организации.

CSV пишется в UTF-8 с BOM и разделителем `;` — открывается в русском Excel
двойным кликом, без импорта и плясок с кодировкой.

Всё найденное дополнительно копится в SQLite (`leads.db`) — повторные прогоны
не дублируют записи, а обновляют их, так что базу можно наращивать неделями и
в любой момент делать срез через `export`.

## Разработка

```bash
python3 -m unittest discover -s tests -t .
```

93 теста, внешняя сеть не нужна: ответы API эмулирует `yandex_nosite/demo.py`.

Структура:

```
yandex_nosite/
  api.py         клиент Search API: ретраи, троттлинг, бюджет, кэш
  geo.py         области, деление на квадранты, справочник городов
  pipeline.py    обход сетки, дедупликация, фильтр, скоринг
  sitecheck.py   классификация «есть ли настоящий сайт»
  scoring.py     оценка лида
  storage.py     SQLite: кэш, база организаций, учёт квоты
  export.py      CSV / JSON / XLSX без внешних зависимостей
  presets.py     наборы рубрик
  demo.py        эмулятор API для тестов и демо-режима
  cli.py         командный интерфейс
```

## Правовая сторона

Данные берутся через официальный API в рамках его условий использования.
Собираются только сведения, которые организации сами публикуют о себе:
название, адрес, рабочий телефон, рубрика. Это информация о юридических лицах
и ИП, а не персональные данные граждан.

Перед обзвоном учтите: реклама по телефону без предварительного согласия
абонента ограничена статьёй 18 закона «О рекламе» (ФЗ-38). Практика такова, что
звонок с коммерческим предложением на **опубликованный рабочий номер компании**
трактуется как деловая коммуникация, а не реклама физлицу, — но ответственность
за способ использования списка лежит на вас. Не используйте выгрузку для
массовых рассылок без согласия и уважайте отказ от повторных контактов.
